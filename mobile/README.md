# qiymetleri.com Android app

Native Expo/React Native client for the public qiymetleri.com catalogue. The existing FastAPI backend remains the data source; admin functionality is intentionally excluded.

## Local setup

```powershell
Copy-Item .env.example .env
npm install
npm run android
```

The default `.env.example` URL targets the public FastAPI deployment. Product and filter requests degrade independently, so one failed endpoint does not discard healthy live data. If the service or its database is unavailable, public catalogue reads fall back to the latest retailer snapshot generated by `scraper/scripts/export_mobile_catalogue.py`. The app visibly labels saved or mixed data together with the snapshot date. The snapshot contains real products, current prices, store links, and image URLs; it never fabricates price history. Set `EXPO_PUBLIC_API_URL` to another HTTPS endpoint to override the deployment.

## Standalone Android APK

The ready-to-install ARM64 APK is stored at
`releases/qiymetleri-1.0.1-arm64-v8a.apk`. It contains the production JavaScript
bundle and does not require Expo Go or a Metro development server.

Install it on a connected Android device with:

```powershell
adb install -r .\releases\qiymetleri-1.0.1-arm64-v8a.apk
```

To rebuild the APK locally, install JDK 17 and the Android SDK, set
`JAVA_HOME` and `ANDROID_HOME`, then run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-android-apk.ps1
```

The script derives the artifact name from `app.json`, verifies its APK signature,
and confirms that the standalone JavaScript bundle is embedded. It uses a short
`C:\qv2` junction because Windows' native toolchain has a 260-character
object-path limit. For an Expo-hosted internal APK build, use
the `preview` profile in `eas.json`; the `production` profile creates an Android
App Bundle for Play Store delivery.
